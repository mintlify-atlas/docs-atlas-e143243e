Every Tau conversation is a **session** — saved to disk as an append-only JSONL file so you can return to it at any time. Sessions are organized by working directory, so resume flows naturally focus on the project you are in. The original JSONL history is never edited; compaction and branching change only the *active context* sent to the provider.

## Where sessions live

Sessions are stored under:

```text
~/.tau/sessions/<cleaned-path>-<short-hash>/
```

For example, `/Users/you/repos/tau` becomes something like `repos-tau-a1b2c3`. The directory name is derived from the canonical working directory path.

## Listing sessions

```bash
tau sessions
```

Each row shows the session ID, title, model, and working directory.

## Resuming a session

<Tabs>
  <Tab title="From the shell">
    ```bash
    tau --session <session-id>
    ```
  </Tab>
  <Tab title="From inside the TUI">
    ```text
    /resume            # open a picker of past sessions
    /resume <id>       # resume a specific session directly
    ```
    The `/resume` picker has a search field that filters by session name or model. Start typing to narrow the list, then use arrow keys and Enter (or click) to select.
  </Tab>
</Tabs>

To deliberately start fresh instead of resuming, use `tau --new-session` (or `/new` in the TUI).

When you quit the TUI and the session was persisted, Tau prints a resume reminder:

```text
To resume this session: tau --session <session-id>
```

## Auto-naming and renaming

New sessions are automatically given a short name generated from the first message. Tau shows the confirmed message first, then performs naming in the background without blocking the transcript update. The name appears in the `/resume` picker and terminal tab title.

To set a name manually at any time:

```text
/name My refactor session
```

Tau will not replace a name you set yourself. Auto-naming makes one provider request; if that fails, Tau uses a short local fallback and continues normally.

## Branching from history (`/tree`)

A session is a tree, not just a linear list — you can go back to any point and try a different path without losing what you had before.

<Steps>
  <Step title="Open the session tree">
    ```text
    /tree
    ```
  </Step>
  <Step title="Select an earlier entry">
    Use arrow keys to highlight any past message.
  </Step>
  <Step title="Choose how to continue">
    - **Enter** — continue from that point, preserving the existing branch.
    - **S** — ask the active model for a structured summary of the messages you are leaving behind before moving the active point.
    - **C** — provide custom focus instructions for that one summary.

    If a summary request fails, Tau falls back to a deterministic summary.
  </Step>
</Steps>

## Context compaction

When a session grows long, use `/compact` to summarize older history and reduce what is sent to the model on the next turn:

```text
/compact
/compact focus on the database migration work
```

Optional text after `/compact` is added as extra focus for the summary. Manual compaction summarizes the whole active context into one summary and fails visibly if the request fails. The original JSONL history is preserved — only the active context view changes.

In the TUI, a running compaction looks like a normal working turn: the prompt activity indicator animates, the terminal tab title updates, and a turn-finished notification fires when it completes while the app is unfocused. Press **Esc** to cancel a running compaction.

## Recovering from interrupted sessions

Older Tau versions could leave malformed tool-call history when a run was interrupted, causing every prompt in the resumed session to fail with a 400 error. Tau now validates the active branch on resume and after `/tree` navigation, repairing missing, misplaced, duplicate, or orphaned tool results by appending a provider-safe branch while preserving the original JSONL entries. Repeating resume is idempotent.

## Exporting sessions

Export a session to a shareable file from inside the TUI or from the shell:

<Tabs>
  <Tab title="TUI commands">
    ```text
    /export                              # HTML into the current directory
    /export --format jsonl               # raw JSONL
    /export --format html report.html    # explicit destination
    ```
    After a successful export, Tau shows the destination path in the transcript (display-only, not saved to session history).
  </Tab>
  <Tab title="Shell commands">
    ```bash
    tau export <session-id>                     # HTML (default)
    tau export <session-id> session.html        # explicit filename
    tau export <session-id> --format jsonl      # JSONL
    ```
    The source can be an indexed session ID or a path to any JSONL session file.
  </Tab>
</Tabs>

### HTML export contents

HTML exports are self-contained and include two interactive tabs:

<CardGroup cols={2}>
  <Card title="Transcript tab" icon="message">
    Preserves the full session tree and entries in storage order. Every entry is a compact accordion row (icon, title, one-line preview, timestamp) that expands to reveal full content. Thinking blocks, tool-call arguments, and tool-result details are nested accordions.
  </Card>
  <Card title="Cache tab" icon="chart-line">
    Summarizes the active branch's model requests, prompt caching, output and reasoning tokens, estimated API-rate cost, tool calls, and compactions. Charts are interactive — hover for exact values, select a legend item to hide a series, and download charts as static PNG images.
  </Card>
</CardGroup>

The export header provides controls to:

- Show or hide tool calls and results in both the transcript and session tree (chip filters show how many entries of each kind the session contains)
- Expand or collapse every accordion at once
- Hide session events (model changes, compactions, labels) to focus on user and assistant messages
- Download the session as JSONL — the complete entry data is embedded in the page, so the download works offline

When `/export` creates HTML from the **live session**, it also includes the current system prompt in a separate, collapsed **System Prompt** section.

<Warning>
Review the System Prompt section before sharing an HTML export. The prompt may expose project instructions, skill guidance, filesystem paths, or other local context. Offline `tau export` of an indexed session or arbitrary JSONL file omits this section because session JSONL does not persist the prompt.
</Warning>

HTML exports follow Tau's themes — `tau-light` in light mode and `tau-dark` in dark mode — and charts recolor live when you toggle the theme.
